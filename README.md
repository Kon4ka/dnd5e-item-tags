# Item Tags for D&D5e

Configurable item, actor and effect tags for Foundry VTT 14 and D&D5e 5.3.3+.

- Create, rename and enable or disable tags in module settings.
- Select applicable item types; optionally tag actors and active effects.
- Use tags in Midi-QOL conditions and Active Effects.
- Optional native item properties and a Custom D&D 5e compatibility adapter.
- Requires libWrapper. Midi-QOL and Custom D&D 5e are optional.

Install the `dnd5e-item-tags` folder in `Data/modules/`, restart Foundry and enable **Item Tags for D&D5e**.

[Full documentation in Russian](README.ru.md)

Automated tests cover data and adapters; live Foundry compatibility is awaiting validation.

## Install and update

After the first successful GitHub Actions release, use this Manifest URL in Foundry's module installer:

```text
https://github.com/Kon4ka/dnd5e-item-tags/releases/latest/download/module.json
```

Every push to the default branch (`master`, or `main` after a rename) runs tests and publishes a release with a versioned ZIP, `module.json`, and commit-based release notes. A multi-commit push produces one release containing those commits. Manual runs are available under Actions. Failed tests prevent publication.

Versions are computed as the source `major.minor.(patch + GITHUB_RUN_NUMBER)`: with base `0.1.1`, run 1 releases `0.1.2`. Re-running a run keeps the same version; completed releases are not overwritten. Keep the workflow file and base version stable; do not copy the generated patch version back into the source manifest. A deliberate major/minor bump can be made in the source manifest. Do not reset the base version backwards or manually publish overlapping version tags.

The packaged manifest points to the stable latest-release feed and a version-specific ZIP. Foundry detects a newer version when the GM checks module updates; this is not an in-session push notification. No commits are generated by the workflow. Release publication uses `GITHUB_TOKEN` with `contents: write`; no personal access token is needed under normal repository settings.

Development checks: `npm test`, `python -m unittest discover -s tests -p test_release.py -v`. Local package preview: `python tools/release.py build` (writes ignored `dist/`, does not publish).
