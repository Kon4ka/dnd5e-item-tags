# Item Tags for D&D5e

Версия 0.1.1. Написано для Foundry VTT 14 и D&D5e 5.3.3. Требуется libWrapper; Midi-QOL и Custom D&D 5e необязательны. Модуль работает в любом мире D&D5e; начальные теги — редактируемые примеры.

При обновлении первой непубличной версии отключите старый модуль `intermezzo-tags` и включите `dnd5e-item-tags`. Старые flags читаются, настройки используются как начальные; затем сохраните настройки нового модуля. Новые изменения эффектов и макросы должны использовать идентификатор `dnd5e-item-tags`. Не включайте обе версии одновременно.

Модуль добавляет редактор собственных тегов и отметки в листах. Он не запускает урон, не меняет HP, состояния, инициативу или правила классов. Теги служат данными для условий и автоматизаций.

## Установка

1. Скопировать папку `dnd5e-item-tags` целиком в пользовательский каталог Foundry `Data/modules/`.
2. Перезапустить Foundry, открыть мир и включить «Item Tags for D&D5e». Включить libWrapper, если Foundry попросит.
3. Настройки игры → «Item Tags for D&D5e» → «Настроить теги».
4. Открыть предмет → «Подробности» → блок «Теги». Также есть кнопка «Теги» в шапке и пункт меню окна. Для существ и Active Effects использовать пункт «Теги» в меню окна.

Инсталляция по URL manifest пока не предоставляется: модуль не опубликован на сервере. ZIP распаковывается так, чтобы файл был именно `Data/modules/dnd5e-item-tags/module.json`, без дополнительного уровня папок.

## Список и отключение

Начальные теги:

| Ключ | Название | Где доступен |
| --- | --- | --- |
| technological | Технологическое | Все Item и эффекты |
| dominion | Доминион | Все Item, существа и эффекты |
| empire | Империя | Все Item, существа и эффекты |
| magic_user | Использует магию | Существа и эффекты |

Можно добавить до 200 тегов. Ключ — латинские строчные буквы, цифры и `_`; начинается с буквы. После сохранения ключ неизменяем: его используют формулы. Название редактируется свободно. Сохранённые теги не удаляются; выключите ненужный.

Для каждого тега выбираются типы предметов из текущей системы: оружие, экипировка (включая доспехи и щиты), инструменты, заклинания, особенности, расходники, контейнеры и остальные доступные типы. «Все предметы» охватывает также будущие типы. Существа и эффекты включаются отдельно.

Выключенный тег скрывается из редактора документа и стандартного списка выбора свойств. API и данные бросков возвращают для него 0/false. Его сохранённые отметки остаются и заработают после включения. Уже сохранённый native property может оставаться видимым как подпись на карточке: это не означает, что API считает тег активным. Для автоматизаций используйте `itags`/API, а не прямую проверку сохранённых `system.properties`.

Мировой переключатель «Включить теги» аналогично выключает все проверки. Это отличается от отключения самого модуля через «Управление модулями»: при отключённом модуле его API и данные бросков отсутствуют.

## Хранение и копирование

Основной источник: `flags.dnd5e-item-tags.tags.<ключ>`, true/false. При включённой интеграции со стандартными свойствами изменение отметки также сохраняет `itags_<ключ>` в `system.properties`, если этот тип Item поддерживает такое поле. Изменение через стандартный список свойств синхронизирует флаг обратно.

Копирование Item и перенос из мировых предметов/компендиума копируют собственные flags. Это независимые экземпляры: последующее изменение шаблона не меняет выданное оружие. На старых предметах отметки автоматически распознаются; массовая перезапись мира при загрузке не выполняется. Определения тегов — настройки мира: при переносе Item в другой мир там должны быть созданы те же ключи.

Старое `flags.world.technologicalWeapon` читается как `technological`, если новый флаг ещё не задан. Явный false нового флага имеет приоритет. При изменении новой отметки старый флаг синхронизируется, и наоборот. Это сохраняет работу прежнего реестра.

**Для поддержки отключения тега и временных зачарований в Разрядном ядре замените код существующего World Macro `ExperimentalCoreDamage` файлом `examples/ExperimentalCoreDamage.js`.** Название макроса, эффект и контроллер ядра остаются прежними. Старый код, который читает только `world.technologicalWeapon`, не знает про выключение тега в настройках и новые временные эффекты. Пример сохраняет прежнее поведение бонуса/критов; он не добавляет вторую автоматизацию урона.

## Условия Midi-QOL и формулы

Модуль через libWrapper дополняет стандартный `getRollData`. Никакой замены функций Midi и обхода его ограниченного окружения нет. Каждое поле — число 0 или 1, уже учитывающее настройки и подготовленные эффекты.

| Что проверяем | Условие Midi |
| --- | --- |
| Технологическая атака | `item.itags.technological === 1` |
| Технологическое оружие Доминиона | `item.itags.technological === 1 && item.itags.dominion === 1` |
| Цель использует магию | `target.itags.magic_user === 1` |
| Оружие Доминиона против такой цели | `item.itags.dominion === 1 && target.itags.magic_user === 1` |
| Метка на владельце | `itags.dominion === 1` |

Для числовых формул: `@item.itags.technological` и `@itags.magic_user` (в roll data самого существа). В контексте Midi с целью также `@target.itags.magic_user`. Не смешивать `@` и JavaScript-строки в одной проверке без необходимости.

Данные цели есть только на этапах, где Midi передал конкретную цель. На раннем этапе выбора целей такой проверки недостаточно. Для нескольких целей бонус, действующий только против части из них, нельзя безусловно добавлять общим DamageBonus всем попаданиям.

В поле условия не пишите `game.modules.get(...)`: Midi ограничивает доступ к глобальным объектам. Публичный API ниже предназначен для обычных макросов и модулей.

## Active Effects, DAE и зачарования

В «Изменениях» эффекта использовать ключ:

```text
flags.dnd5e-item-tags.tags.technological
```

Режим **Override / Переопределить**, значение **1** для включения или **0** для выключения. Для другого тега заменить последний сегмент. В Foundry 14 нативный тип изменения называется `override`; числовой mode для совместимых редакторов — 5. Не использовать Custom/Особая: у тегов нет собственного обработчика Custom.

Чтобы изменить тег оружия временно, изменение должно применяться **к Item через настоящее применённое зачарование D&D5e**. Обычный эффект на Actor меняет Actor, а не весь его инвентарь. Удаление зачарования вернёт базовый флаг; модуль не сохраняет подготовленные эффектом значения в предмет.

Блок «Теги» редактирует постоянную отметку. Если подготовленное значение отличается, он показывает подпись «включён/выключен эффектом». Нативный `system.properties` зеркалирует базовое значение; временные изменения flags проверяются через `item.itags` и API.

У эффекта есть два разных применения:

- Отметить **сам эффект** через меню «Теги» — например, его происхождение «Империя». Отметка сохраняется при обычном копировании этого эффекта. Она не меняет автоматически теги Item-источника.
- В «Изменениях» эффекта задать указанный выше путь — выдать/снять тег **документу, на который применяется эффект**.

`actorHas` и Actor roll data дополнительно учитывают метки на `actor.appliedEffects`, только пока эффект активен и не подавлен. Предметы в инвентаре сами по себе не делают владельца магом или доминионцем.

## API

```js
const tags = game.modules.get("dnd5e-item-tags").api;
tags.has(item, "technological");
tags.all(item, ["technological", "dominion"]);
tags.any(item, ["empire", "dominion"]);
tags.actorHas(target.actor, "magic_user");
tags.map(item); // { technological: 1, dominion: 0, ... }
tags.actorMap(actor);
tags.raw(item, "technological"); // базовое чтение без фильтра enabled; для диагностики
tags.raw(item, "technological", { source: true }); // именно сохранённое, до эффектов
await tags.set(item, "technological", true);
await tags.sourceHas(effect, "empire"); // метка эффекта или Item из effect.origin
tags.open(item); // редактор отметок
tags.definitions(); // копия списка тегов
```

`sourceHas` не принимает принадлежность владельца к Империи за доказательство происхождения защиты. Если origin утрачен, он не угадывает источник. Для будущей автоматизации удобнее помечать конкретный защитный эффект или заклинание-источник.

## Убеждённый Доминионец: что обеспечивает модуль

Пометьте оружие тегами `technological` и `dominion`; существ, которых мастер считает использующими магию, — `magic_user`; имперские заклинания/защитные эффекты — `empire`. Для различения щита и источника временных HP можно создать `shield` и `temp_hp_source` и разрешить их для эффектов/заклинаний.

Это даёт точные условия для отдельной автоматизации перка. Сам модуль тегов **не реализует** обход щитов/temp HP, дополнительный кубик оружия или преимущество спасбросков. В частности, числовое поле временных HP D&D5e не хранит автоматически, какая его часть создана Империей: источник нужно отслеживать в момент выдачи. Метки достаточно для классификации источника, но недостаточно для восстановления истории уже полученных temp HP. Дополнительный «кубик оружия» также следует брать из выбранной Activity, а не всегда заменять на d8. Для смешанного набора целей потребуется отдельная обработка каждого попадания.

## Custom D&D 5e и другие модули

Свойства регистрируются в `CONFIG.DND5E.itemProperties` и существующих `validProperties`. Собственные ключи имеют префикс `itags_`; чужие записи не заменяются. Поля системы и классы листов не переписываются. Custom D&D 5e в изученном исходнике включает внешние свойства в свой редактор. Также поддерживается его хук `customDnd5e.setItemPropertiesConfig`: после перестроения конфигурации восстанавливаются только наши записи.

Источником названий, разрешённых типов и enabled для `itags_…` остаются настройки **этого** модуля. Редактировать те же параметры одновременно в двух редакторах не нужно: наши настройки имеют приоритет. Подхват внешних свойств исследован по исходникам Custom D&D; живой совместный тест не выполнен. Модуль не зависит от его внутренних файлов и работает без него.

Штатные свойства доступны там, где D&D5e поддерживает `system.properties`. Для остальных Item работает собственный блок/редактор flags. На нестандартном листе без штатной вкладки Details используйте меню окна «Теги»; листы ApplicationV1 в этой версии не поддержаны.

Если выключить или удалить сам модуль, flags сохраняются, но исчезают API и регистрация свойств. Не редактируйте массово предметы с неизвестными свойствами после удаления интеграции: сначала верните модуль либо подготовьте миграцию. Автоматического разрушительного очищения данных нет.

## Проверки

`npm test` — автономные проверки данных и адаптеров с имитацией Foundry: наследование старого флага, явный false, отключение/включение, native flags sync, сохранение чужих свойств, копирование, scoped tags, эффекты, условие в Midi-подобном sandbox, права API. Эти тесты не заменяют живой запуск Foundry.

Перед использованием в игре:

1. Создать мировые оружие, доспех, инструмент и заклинание. Пометить, закрыть и открыть листы.
2. Скопировать предмет и перетащить на персонажа. Проверить независимость копий и сохранение после перезагрузки.
3. При двух ведущих изменить тег/его enabled, проверить результат на обоих клиентах.
4. Запустить ядро с примером макроса: обычное/технологическое оружие; затем отключить тег и повторить.
5. Временно выдать/запретить тег зачарованием, снять зачарование; проверить возврат базового значения.
6. Если установлен Custom D&D — открыть его Item Properties, сохранить, перезагрузить, повторить проверки отметок. Проверить развитие персонажа отдельно от тегов.
